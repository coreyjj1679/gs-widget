# 2026-10-25 黑色商團營地與道具頁調整前後量測

本輪在 Apple M5、24 GiB、macOS，以 1.2.1 release、應用程式原生預設 renderer 比較調整前後；未另外確認 renderer 名稱。視窗為 1414 × 907 邏輯像素、2× 縮放，全模式，legacy／battle／gallery 均關閉。實際語言為 **zh-en**：現場設定頁確認主要中文、次要 English，設定檔在 baseline 前已是此組合且未變更。量測時沒有並行編譯，沒有清除 OS 快取。

兩輪都先開道具暖身再回總覽，接著固定依序進入怪物目錄、黑色商團營地、道具入口、材料，共五輪。只統計 `navigation.*` ordinal **1–20**；ordinal 0 暖身及 21 之後的 UI 回歸操作排除。「首次」是這套順序內第一次量測，尤其道具入口已暖身，不能稱為冷啟動。解析器也在後續 `detail.open` 開始時截斷片段；最後 ordinal 20 最多觀察 1,000 ms，避免把一分鐘後的點選誤算進來。

以下為 `ui.update_to_render`：更新開始至首個渲染通知完成，不包含滑鼠事件派送前等待、顯示器呈現或全部圖示載入。重訪為後四輪中位數，括號內為最小–最大，單位均為 ms；箭頭為調整前 → 調整後。

- 怪物目錄：首次 **25.60 → 16.52**；重訪 **52.51（46.99–57.68）→ 15.05（9.78–15.62）**。
- 黑色商團營地，12 筆：首次 **31.43 → 26.73**；重訪 **11.55（10.41–13.59）→ 14.41（10.45–14.83）**。
- 道具入口，27 個目錄項、169 個結果：首次 **46.58 → 9.73**；重訪 **20.91（19.62–24.64）→ 11.96（11.35–12.66）**。
- 材料，1,920 筆：首次 **78.12 → 37.49**；重訪 **59.62（56.69–61.33）→ 34.79（31.98–36.92）**。

營地首次同步資料準備為 **9.35 → 6.51 ms**，材料為 **8.50 → 6.72 ms**。這取自單一外層 `list.publish`／`list.reload_board`，已包含內層查詢與模型工作；不能與內層 spans 或首幀時間相加。每個情境只有一次首次及四次重訪，這些是觀察值，不能將全部差異歸因於單一修改。

圖示流程有明確取捨：營地首次排入工作 **154 → 83**，省去完整模式沒有使用的舊式掉落縮圖工作；材料仍為 **1,867 → 1,867**。待處理 UI 批次的觀察峰值，營地 **6 → 1**、材料 **60 → 1**；材料最長單批排隊時間 **70.48 → 27.93 ms**。重訪均沒有新圖示工作。

材料首批 `icon.paint` 完成提早到導覽後 **81.26 → 8.32 ms**，但最後一批延後為 **90.76 → 314.98 ms**，其後第一個渲染通知為 **149.74 → 320.14 ms**。營地首批為 **36.64 → 37.00 ms**、最後一批 **37.05 → 46.63 ms**，其後渲染為 **42.35 → 54.44 ms**。限制批次後，首幀與首批圖示可較早出現，背景圖示分批補齊的尾端時間則變長；營地重訪首幀也略慢，不能宣稱所有載入指標都改善。

兩輪每個樣本的 queued 工作數都與 `icon.paint` target 計數相等，片段結束時沒有觀察到未開始回填的批次；材料首次為 1,867 個 target，調整後 59 批。這支持本輪沒有遺漏已排入的回填工作，但 target 計數包含失敗與嘗試更新，不代表所有圖片成功載入或已呈現在螢幕。

這是 **macOS 上的本地比較，沒有證明 Windows Ryzen 9 的一秒停頓已解決**。完整 Windows 客戶端的磁碟與圖片成本仍需在該機器重測；本輪程式碼尚未發佈。沒有將畫面截圖或個人設定存入儲存庫。
