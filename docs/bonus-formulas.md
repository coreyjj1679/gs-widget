# 紅利計算依據

核對日期：2026-10-24。這是離線計算器的維護文件；客戶端資料提供兵種、屬性、關係、正式經驗表及升級點數，公式由程式明確套用。巴哈及 Geota 僅用於獨立回歸核對，不是執行時依賴。遊戲資料能確認的範圍與仍待確認的規則見 [遊戲資料稽核](bonus-game-evidence.md)，實際外部核對見 [Geota 記錄](bonus-geota-crosscheck.md)。

## 資料庫已有的資料

`data/gersang.db` 有 311 筆 `characters`、296 筆 `character_stats`，涵蓋非座騎角色的基本屬性。15 位傳說將帥的材料與升級鏈均已存在。

- `job_steps`：364 筆；`kind=1` 為 107 筆／29 條鏈，`kind=2` 為 182 筆／58 條鏈，`kind=3` 為 75 筆／15 條傳說鏈。
- `job_materials`：75 筆傳說鏈材料記錄。
- `character_upgrades`、`character_companions`：其他轉職與合成關係。
- `character_stats`：力、敏、體、智的基礎值。
- `strings`：客戶端公式說明，沒有結構化的紅利規則表或現成紅利計算引擎。

印度普通傭兵的 `job_steps` 從印度兵開始，沒有列出四國傭兵的可選轉換來源；例如大刀兵的 chain 46 是 `D117 → D118 → T26 → T78`。但 bundled DB 的招募說明已包含來源：`strings` 的 `OnlineText.dat / 00015131–00015139` 分別列出九種印度普通兵的四個選項及 100 級要求。大刀兵 `D117` 的 `hire_gts=15133` 明列刀手、劍術浪人、大刀武士、斧頭巨漢。

紅利引擎已根據原始客戶端的編號關係補上這九組選項，不修改 `job_steps`，也不把四個選項當作四隻合成材料。每組只使用所選來源的等級，作為印度兵的繼承紅利；資料來源與編號對照見「印度來源選擇」。

四隻新幻獸的結構化轉職關係亦缺漏，客戶端 `OnlineText.dat / 00032396` 已列明材料及 `/30`。計算器已據此補上限定代碼的後備關係：水龍 `T116 ← E36,E37,E38`；風龍 `T117 ← E42,E43,E44`；火龍 `T121 ← E39,E40,E41`；雷龍 `T122 ← E33,E34,E35`。後備關係只在結構化資料缺漏時使用。雷龍材料是巨山、白龍、鐮刀者；第三方頁面的犬神名稱不可覆蓋客戶端記錄。[官方火龍／雷龍公告](https://gs.mangot5.com/game/gs/notice/detail/?contentNo=51961) 亦列出相同材料。

## 計算定義

`B` 為力、敏、體、智的基礎總和，`L(level)` 為升級所得點數，`H` 為上一階段繼承紅利，`W` 為白衣從軍累計點數。沒有裝備的總點數為 `B + L + H + W`；公式中的「純點數」排除裝備，白衣是否排除則由各規則決定。

計算器每次轉職完成後捨去該次結果的小數，再把整數紅利帶到下一階段。不同素材先合計，再依目標公式相除；不要先把每件素材的貢獻個別取整。此順序經獨立養成案例與 Geota 實際輸入核對；現有客戶端資料未包含完整伺服器程式，不能宣稱已從遊戲程式反解所有取整操作。

已核對的規則：

- 四國普通傭兵、一轉、二轉、改造／覺醒將帥：前身的非白衣點數 `/ 5`，保留完整白衣點數。[紅利公式](https://www.52jushang.com/qita/hongli.asp)、[傳說將帥轉職解說](https://forum.gamer.com.tw/G2.php?bsn=5079&sn=504)。
- 四國合體怪：三隻素材的**等級平均**，不是屬性平均。[合體怪資料](https://www.52jushang.com/yongbing/2guaiwu.asp)。
- 凶獸及新幻獸：三隻合體怪的純點數總和 `/ 30`；其覺醒為前身純點數 `/ 10`。[凶獸資料](https://www.52jushang.com/yongbing/5monster.asp)、[新幻獸資料](https://www.52jushang.com/yongbing/5monster2.asp)。
- 神獸：三個幻獸石像等級的平均；麒麟：四個神獸石像等級的平均。輸入值是石像等級，不能直接代入封印前的傭兵等級或屬性。[神獸資料](https://www.52jushang.com/yongbing/4monster.asp)。
- 四天王：兩隻神獸的純點數總和 `/ 10`。
- 冥王：兩隻材料的純點數總和 `/ 10`，包括精靈素材。[官方不動明王改版頁](https://landing.mangot5.com/template/gs/event/220113_fudomyojin/index.html)、[冥王資料](https://www.52jushang.com/yongbing/mingwang.asp)。
- 覺醒四天王、覺醒冥王：前身純點數 `/ 5`。
- 傳說將帥：四隻材料的非白衣點數總和 `/ 20`，加上四隻材料白衣點數總和 `/ 4`。傳說將本身不能使用白衣。計算器在兩部分相加後取整；來源未提供「兩部分各自取整」的獨立證據，因此不可擅自改成兩次截斷。

例：某階段純點數為 `6661`，`/ 10` 後得到 `666`；下一階段只能繼承 `666`。傳說材料非白衣總和 `14641`、白衣總和 `1200`，紅利為 `floor(14641 / 20 + 1200 / 4) = 1032`；後一例可與指定討論中的望月千代女計算核對。

外部獨立核對的全階段 250 級案例：`T80` 神弓朱蒙為 `719`，四隻材料各有白衣 300 時為 `1019`；`T81` 舞姬貂蟬為 `723`／`1023`。[韓服完美傳說養成記錄](https://gilboung.tistory.com/90) 明列含白衣的最大值；這兩條四國鏈的非白衣值即各減去 300，可用於資料庫整合測試。

## 等級點數

計算器的材料等級上限依種類限制：一般兵種 250 級，四天王、傳說將帥及冥王 260 級，石像 200 級。預設填入 250 級，石像則填入 200 級；已確認轉職最低等級高於 250 時會升至該下限，例如覺醒天王／明王的前身預設 260 級。「全部滿級」會將各素材設為自己的等級上限，石像限制為 200 級。「全部 200 級」同樣遵守已確認的轉職下限，須 260 級的素材維持 260。手動輸入超過該材料上限時顯示錯誤。印度普通兵的四國來源限制為 100–250 級；已核對的普通兵、將帥、傳說及覺醒王種轉職下限也會套用。石像限 100–200 級、每 10 級一格。未知條件不猜測，也不作完整任務／道具／國籍資格檢查。新合成的目標按 1 級計算。

260 級擴張的客戶端證據為 `QuestText.dat / 00021278`：明列四位四天王、五位明王（含不動明王），以及十五位傳說將帥。原始客戶端 member 747 的 `extra_gcs_0747` 另記錄 `NeedLevel=250`、`ResultLevel=260`。因此傳說也屬可擴張至 260 級的類別；新合成的傳說作為目標仍按 1 級輸出，不能把目標未來的 260 級點數加回本次合成紅利。

`L(1)=0`。下面的區間包含上下界，表示**升至該等級**獲得的點數；從 2 級累加至輸入等級。


回歸核對點：`L(100)=396`、`L(120)=477`、`L(150)=682`、`L(200)=1306`、`L(212)=1507`、`L(245)=2156`、`L(250)=2256`、`L(260)=2466`。[52 巨商經驗表](https://www.52jushang.com/qita/zhandou_exp.asp) 與 [거상짱計算器](https://www.gersangjjang.com/point/hong.asp) 的區間相符。不可線性插值，也不可使用每十級固定增量。

## 印度與白衣

- 四國傭兵／怪物轉成印度普通兵／怪物：獲得來源角色的 **100% 等級** 作為紅利。[石弓手](https://www.52jushang.com/yongbing/india/sukgong.asp)、[印度北部](https://www.52jushang.com/yongbing/india_n.asp)、[陸地巨龜](https://www.gersangjjang.com/yongbing/india/yukji.asp)。
- 印度一轉與二轉：白衣也參與前身點數 `/ 5`，完成轉職後仍保留白衣。印度覺醒起改為先排除白衣再除，最後保留白衣。印度將帥使用白衣會清掉先前的四國兵轉換紅利。[指定討論的白衣說明](https://forum.gamer.com.tw/C.php?bsn=5079&snA=12729)。
- 印度合體怪：三隻印度素材的純點數總和 `/ 10`，與四國合體怪不同。[提亞瑪特規則](https://www.gersangjjang.com/yongbing/india/tiamet.asp)、[不動明王分層計算器](https://www.gersangjjang.com/point/budong.asp)。
- 愛羅婆多：三隻印度合體怪的純點數總和 `/ 30`。[當年改版公告內容](https://www.games.idv.tw/news.php?nid=18110)。

印度材料將可以明確選擇「在四國兵階段完成白衣，再轉印度」。此選項預設關閉；開啟後，現有白衣點數 `W` 會帶入印度一轉及二轉的前身點數 `/5`，印度覺醒的 `/5` 則排除 `W`，並保留最初的四國轉換等級紅利。白衣點數本身一直獨立保留，在最終傳說公式以 `/4` 計算。此歷程與先轉印度、再用白衣清掉四國轉換紅利不同，不能自動假定。[韓服養成歷程說明](https://gall.dcinside.com/mgallery/board/view/?id=gersangm&no=682153) 可與下述巴哈數值逐階核對。

若中途使用白衣、降階或重練，不屬於上述明確歷程，應輸入實際非白衣「既有紅利」。未確認白衣歷程且未填實際值時，印度材料不會產生看似完整的答案。既有紅利欄不應重複包含基礎、等級或白衣點數；空白表示照鏈計算，`0` 表示已確認沒有繼承紅利，兩者不同。計算器未模擬任意次序的每次白衣使用，也未模擬重生系統。

### 印度來源選擇

原始解析庫 `gs-parser/data/gersang-full.db` 的 `raw_sheet` 指向 `gersang.gcs` member 749：`JobChangeList_Nepar_India.txt`，資料表為 `extra_gcs_0749`。九筆印度普通兵記錄的 `Upgrade Step=0`、`Need Level=100`，`Need Mon1` 至 `Need Mon4` 是四選一來源。其後的一轉、二轉記錄各自只有一個來源，不能與四選一記錄混合解讀。

顯示名稱取自 catalog；招募文字中的「槍炮浪人」「火炮手」與 catalog 的「鐵炮浪人」「火砲手」有字形差異，因此關係依數字編號建立，不靠模糊名稱配對。此轉換只使用來源等級，不將來源的基礎屬性、升級點數或既有紅利加入結果。

實作以 `BonusNode.predecessor_options` 保存 OR 選項，與 `children` 的 AND 材料分開。`BonusInput.predecessor` 存所選 catalog 編號；空白採第一個來源，明確填入不存在的編號則報錯。每個來源輸入的穩定 key 是所屬印度節點完整路徑加 `/choice:<catalog code>`，例如直接計算大刀兵時為 `D117/choice:U86`。相同兵種出現在不同材料路徑時各自獨立；切換來源保留先前分支的等級，未選分支不參與計算或驗證。

例如選用 200 級刀手轉成大刀兵，新大刀兵的轉換紅利為 `200`；之後以 250 級大刀兵轉法治羅 `D118`，使用 `(大刀兵基礎總和 + L(250) + 200) / 5` 取整。若這隻大刀兵已用白衣清掉四國轉換紅利，應在**大刀兵節點**的「既有紅利」填 `0`，以取代來源歷程；留空會重新按所選來源計算。不能把後續印度將的所有繼承紅利一律清成 `0`，該階段應填實際非白衣紅利。手動覆寫生效時，已被取代的來源選項與舊輸入不阻擋計算。

## 無重生上限與完美判定

`calculate_max_bonus` 以目前選中的來源路線建立獨立輸入，將每個使用中的材料設成自己的等級上限：一般材料 250、石像 200、可擴張的天王／明王／傳說 260。它忽略未完成的等級草稿及手填繼承紅利，保留四選一來源；遇到未確認的前置資料則回報無法計算，不用 `0` 代替未知歷程。傳說上限使用四隻最終材料各白衣 300；印度材料使用「四國兵階段完成白衣，再轉印度」的已確認養成方式。

「完美」比較的是**每次轉職取整後的最終紅利**是否等於此上限，不要求每隻材料都滿級。怪物、幻獸、神獸、天王、明王與已確認的傳說公式可作「無重生完美」判定。普通將帥目標的結果只提供「無白衣／無重生上限」基準，不能以此宣稱涵蓋全部白衣歷程的完美；有手填繼承紅利時，介面也不自動確認完美。重生可提高部分結果，所以此標籤不能省略「無重生」。

[巴哈明王討論](https://forum.gamer.com.tw/C.php?bsn=5079&snA=12582) 的 2025 更新文字列出覺醒後無重生完美值：覺醒軍茶利 `V29=976`、覺醒金剛夜叉 `V28=956`、覺醒大威德 `V27=955`、覺醒降三世 `V26=968`。正文的五張圖片是**為覺醒壓低養成等級的未覺醒明王**，不能把圖中的數字當成該階段自己的上限：

- 軍茶利：普通怪 104、合體怪 196、混沌 245、覺醒混沌及三尾狐 250，得到未覺醒紅利 `664`；明王升至 260 後覺醒仍為 `976`。
- 金剛夜叉：普通怪 176、合體怪 197、窮奇 247、覺醒窮奇及小青龍箭士(水) 250，得到 `664`；260 覺醒後為 `956`。
- 大威德：普通怪 174、合體怪 193、檮杌及後續材料 250，得到 `659`；260 覺醒後為 `955`。
- 降三世：普通怪 141、合體怪 188、饕餮 240、覺醒饕餮及小火蜥蜴(火) 250，得到 `674`；260 覺醒後為 `968`。

全階段設成各自上限時，未覺醒軍茶利、金剛夜叉、大威德、降三世、不動明王的紅利分別為 `666 / 665 / 660 / 677 / 726`。不動以 260 級純點數 `/5` 可核對文章的覺醒結果 `988`，但目前 catalog 沒有覺醒不動條目，計算器不虛構可選角色。

## 維護限制

未建立可靠鏈或規則時要求輸入實際紅利，不應以零值補齊或套用另一兵種的除數。神獸石像、活動／證書兵、精靈初始紅利也需要分開辨識。計算器已為小白熊 `F40` 加入固定雇用紅利 500，獨立於資料庫的基礎總和 400；「既有紅利」留空時自動使用 500，明確填值則覆寫這項紅利，不會重複相加。[證書怪物資料](https://www.52jushang.com/yongbing/guaiwu_zhengshu.asp) 與不動明王計算器可交叉核對。

外部計算器只作交叉核對：`gersangelacal.com` 的不同計算頁曾使用不一致的等級區間及取整方式；`gersangjjang.com` 部分頁面只在顯示時取整。不要直接複製第三方演算法，應優先保留來源、邊界測試及客戶端證據。


## 最低總經驗的完美配置

「最低經驗完美」固定目前的四選一路線，將每個受支援的白衣素材視作已完成 300 白衣、無重生，搜尋能達到同一最高整數紅利的配置。它最小化的是**升級樹內各素材從 1 級練起的累積經驗總和**，並非等級總和、逐隻獨立壓低的下限或平均等級。白衣反覆重練、購買已練好的兵、經驗加成、招募與任務／物品成本，以及石像背後未展開的養成歷程不納入此數字。石像節點以封印來源從 1 級練至記錄等級的累計 XP 作為估算成本，不包含其更早合成。

正式 XP 來源是 `gersang.gcs` member 7 的 `ExpForLevelUp.dat`；member 18 是 `Test_ExpForLevelUp.dat`，不可混用。正式表 250 級累積 30,000,000,000 XP，260 級為 300,000,000,000 XP。程式以整數精確比較，避免把兩張表的差異（250／260 級累計值相差三倍）或浮點誤差帶進最佳化。

動態規劃狀態記錄每個節點相對全滿配置損失的屬性點數，以及能節省的最大總經驗；先合併子樹，再依該次轉職的實際除數向下取整。最終只接受紅利損失為零的狀態，並還原整組可同時使用的等級。每個節點遵守已知最低／最高等級及石像的離散等級限制。輸出的配置再交回正常紅利引擎驗算，確保仍等於上限。未知歷程不能取得「完美」或最低經驗規劃。

「全員白衣 300」只修改可使用白衣的素材，不覆蓋手填歷史紅利；印度自動計算路線會同時明確選用「四國兵階段先完成白衣」假設。「最低經驗完美」則套用完整的理論養成配置，取代手填歷史。之後手動修改任何欄位，先前的最低經驗結果標記會清除。
